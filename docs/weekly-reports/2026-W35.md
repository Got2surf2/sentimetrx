### Narrative (from devlog)

**Reliability: an unmeasured value must never render as a measured one (Aug 17)**

- `lib/entityFilter.ts` — `count_entity_terms` was timing out at 57s on large scopes (12 Sentry events from the entity-discovery cron); the error was logged and swallowed, and the empty result was **indistinguishable from a measured zero**. `storeEntityMentionCounts` was then durably persisting those zeros via `apply_entity_mention_counts`, and default reads dropped zero-count entries — so a transient timeout blanked the entity catalog.
- Fix: `computeEntityCounts` returns `failed: boolean`; the durable write refuses on failure (previous counts stay), the background store-refresh is skipped, the zero-count drop is suspended, and `counts_failed` is exposed on `EntitiesResult`. A flag, not a throw — callers decide.
- 4 new tests in `tests/unit/entityCountFailure.test.ts`; 2 of the 4 verified to fail against the pre-fix code (not vacuous). This is the same lesson the substantive-count metric-strip bug taught in W33.

**TextMine first-open experience (Aug 17)**

- **Blank content area on first open**: the loader was gated `!rowsLoaded && rowsLoading && !rowsError && !themesPaintable`, but `startRowFetch` only fires after the server-counts request finishes. Message is now phase-accurate: "Counting themes…" before row fetch starts, "Loading dataset rows… N%" after. Browser-verified on the 128,619-row Outback set.

- **Word modal share%**: was a share of the whole corpus, so every chip in a 9%-theme squeezed into a 0–9% band. Now expressed as share of the theme the word was opened from (which required a scope-source fix mid-stream when the first attempt used the wrong theme). Ungrouped/flat cloud keeps the corpus denominator by design.
