## Dimensions: rating-based sentiment fallback for neutral "who" subs (Aug 7)

WHY: On the Flemings dataset the "Service — who served you" sub-cards (Server, Manager, Chef) showed "No sentiment signal" despite carrying star ratings and large mention counts. Cause is by-design: the `touchpoint` axis entities are all *neutral* keyword phrases (`lib/taxonomyKeywords.ts:44` — "Pure category words: polarity neutral, context fills in pos/neg"), so they accumulate mention counts but never pos/neg assertions → `posPct` stays null → "No sentiment signal", even though the sibling `attribute` axis carries the actual service sentiment. Fix: when a sub has no polarised mentions (`pos+neg == 0`), `posPct` now falls back to the **star ratings of the mentioning reviews** (share rated ≥4★), consistent with the Ratings-=-all-reviews principle and the emotion axis's existing ≥4/≤3 rating split. New `SubStat.sentBasis` (`'keyword' | 'rating' | null`) records the method so the card labels the fallback "· by rating" and the footnote stays honest — the two denominators are never silently blended. Touches `lib/taxonomyRollup.ts` (accumulate subPosRows/subNegRows, finalize fallback) + `components/analyze/TaxonomyModule.tsx` (label) + `docs/TAXONOMY.md`. Requires a rollup refresh (re-run the keyword classify on the Dimensions tab) to regenerate the stored rollup — the fallback reads only already-embedded row ratings, so no row re-classification is needed. tsc clean; 1602 tests green (3 new rollup cases).

## Analyze: fix "Manage members → Save changes does nothing" on collections (Aug 7)

WHY: Owner reported adding a dataset to a collection and clicking Save changes did nothing. Root cause was a stale-closure bug in `AnalyzeClient.tsx`, not the modal or the API — the add always succeeded server-side. `ManageMembersModal.save()` calls `onChanged()` then `onClose()` synchronously in one tick; `onChanged` did `setManageDirty(true)` and `onClose` read `const dirty = manageDirty` to decide whether to `window.location.reload()`. Both callbacks are closures from the same render, so `onClose` saw the pre-update `false`, skipped the reload, and the grid never refreshed — the member was in the collection but invisible until a manual page refresh, which read as "Save does nothing." Fixed by tracking the dirty flag in a `useRef` (readable synchronously in the same tick) instead of `useState`. Swept the class: no other parent reads a sibling-callback-set state value synchronously in an onClose. tsc clean; 1602 tests green.

## Classify: auto-retry the transient statement-timeout on the verdict write (Aug 7)

WHY: Owner hit "Couldn't classify — Classification failed: HTTP 500" enabling Dimensions on a ~4.5K-row dataset locally; "Try again" then worked. Root cause is a Postgres statement timeout (57014) on `apply_taxonomy_verdicts` in `embedVerdicts` (`lib/taxonomyClassify.ts`) — the 500-row write crosses the timeout when the DB is momentarily slow / under the concurrent read load the Dimensions tab fires (signal-stats + rows + theme-counts all at once). Unrelated to the same-day Dimensions sentiment-fallback change (that lives in the rollup step, which runs after the write and is already try/caught). Since the RPC is an idempotent upsert per (row, fieldKey), re-applying the same batch is safe: `embedVerdicts` now retries a *transient* failure (57014 / timeout / connection-reset messages) up to 3 attempts with 0.5s/1s backoff, turning the manual "Try again" into an automatic recovery instead of a user-facing 500. A non-transient error still throws immediately. tsc clean; 1602 tests green.

## One-off: Trump corpus builder — everything he said or posted since the inauguration (Aug 7)

WHY: Owner asked for a research corpus of Trump's speech — official speeches plus the ad-hoc material — and everything posted online, back to the 20 Jan 2025 inauguration, then narrowed it mid-build to exclude executive orders and other legal instruments "unless there is narrative in there that gives me a perspective of what is going on in his mind". Added `scripts/oneoff/_trump_corpus_fetch.ts` (not wired into the app; writes to ~/Downloads/trump-corpus). Two free key-less sources: GovInfo DCPD (official record, public domain — package IDs from the per-year sitemaps, one HTML fetch per package for title/date/full text/speaker labels, disk-cached so re-runs are free) and the CC0 Truth Social archive via its CNN mirror (always re-fetched, since a cached copy would silently truncate recent posts). Federal Register was evaluated and dropped as pure duplication — DCPD already carries EOs in full text.

The corpus's value-add is speaker attribution: DCPD renders each turn as `<p class="s2">The President. <span class="p">…</span></p>`, so `trump_text` holds his words only while `text` keeps the full exchange — without that split, reporters' questions get scored as if he said them. QC caught two real bugs: DCPD switches the label to "President Trump" whenever a foreign head of state is present, which had left 112 bilateral meetings and joint news conferences with an EMPTY `trump_text` (fixed → 3, all genuine "no transcript was provided" notes); and a naive prefix match would have swallowed "The President's daughter-in-law Lara J. Trump", so the matcher anchors on `(\.|\s|$)` and caps label length. Verified "Mr. Trump" in the Turning Point call is Donald Trump, Jr., correctly excluded. The CSV ships a 500-char excerpt rather than transcripts, because single documents exceed 130,000 chars and Excel silently truncates any cell over 32,767 — full text is in the NDJSON. Excluded legal/administrative documents are written to a side file WITH full text so anything with a narrative preamble can be recovered without re-fetching. Result: 11,279 items (696 spoken/statement + 10,583 posts), 2.78M Trump-attributed words. Known gap documented in the manifest: DCPD lags ~5 weeks so the spoken record ends 1 Jul 2026 while posts run to today; whitehouse.gov cannot fill it (its sitemap carries exactly one remarks transcript). tsc clean.

## One-off: Trump corpus ingested into Sentimetrx as two datasets (Aug 7)

WHY: Owner wants the core themes and how they shift over time, and explicitly wants OUR OWN AI extraction rather than relying on the external Federal Register subject headings. Added `scripts/oneoff/_trump_corpus_ingest.ts` → TEST project by default (`--target prod` must be typed explicitly).

TWO datasets, not one, for three separate reasons that happen to agree: (1) pooled, the 10,583 posts would swamp 696 spoken documents and any "theme share" would really be measuring Truth Social; (2) combined they are 56,731 rows, over the 50K threshold where Statistics switches to sampling — split they are 49,046 and 7,685, both under; (3) the OFR subject headings only exist on the spoken side. Row granularity is the other load-bearing decision: whole spoken documents run a median 2,317 words and up to 18,927, far too long to be one verbatim (themes come back generic), so the spoken side is split on paragraph breaks → median 40 words, the size the extractor is tuned for, with sub-15-word fragments ("Yes." / "Thank you.") dropped.

Per owner mid-build: the pre-existing tags are FIELDS and never folded into the body — if they were concatenated into `text` the extractor would rediscover them and we would have proved nothing. Three shapes: `ofr_subjects` (raw), `ofr_subject_tags` (1,922 full headings), `ofr_topics` (collapsed to the head term before the comma → 1,127, the grain you actually chart). Verified post-ingest that no subject tag string appears in any `text`. That leaves the labels usable as a professionally-labeled calibration set: run our extractor on the spoken side, check it against the OFR labels, then apply it to the unlabeled posts with a known error rate.

Also caught during verification that 1,047 posts (13.6% of those with text) are reposts carrying an `RT @` prefix — someone else's words. Previously listed as an un-closable gap in the corpus manifest; now a filterable `is_repost` field, kept rather than dropped since sharing is still a signal of attention. Owner also resolved the reporter-agenda confound in the other direction: he frequently ignores the question and pivots to his own point, so the theme that surfaces is his regardless of what prompted it — that bias is accepted deliberately rather than engineered around. Resolves org/user against whichever DB it targets (test project carries orphan [CLONE] orgs with no members; membership is `users.org_id`, not a join table). tsc clean; 49,046 + 7,685 rows verified against row_count.

## Fix: scripted dataset ingest must create dataset_state AND a detected schema (Aug 7)

WHY: The Trump corpus ingest produced datasets that existed, had correct rows, and were unusable — owner hit a bare 404, then (after a partial fix) a Schema tab with no fields and a disabled "Mine with AI". Two separate omissions, both because `scripts/oneoff/_trump_corpus_ingest.ts` was modelled on `scripts/pilot-rc-ingest.ts`, which inserts rows and stops. The existence of `scripts/repair-review-dataset-state.ts` in the repo was the standing evidence that this template is incomplete, and I should have read it as such.

(1) **`dataset_state` row.** `app/analyze/[datasetId]/layout.tsx` and every tab call `notFound()` when it is missing — hence a 404 rather than an error, since to the router the page genuinely does not exist. (2) **Detected schema.** An empty `schema_config` is not enough: the upload route (`app/api/datasets/route.ts`) inserts `emptySchemaConfig()` but the CSV flow then runs `autoDetectSchema(rows)` and stores the result. Without it the Schema tab renders zero fields and TextMine reports "0 open-ended fields", which disables mining. `mergeSchemaStats` cannot substitute — it returns early when `schema.fields` is empty.

(3) **Detection over-reach, caught by the new check.** `autoDetectSchema` classified `ofr_subjects`, `ofr_subject_tags`, `ofr_topics`, `ofr_categories` and `doc_title` as open-ended (they are long multi-word strings), which would have handed the Federal Register's own tags to the theme miner — the AI would "discover" themes that are just the pre-existing labels read back, defeating the whole point of keeping tags out of the body. Now only `text` may be open-ended; everything else is demoted to categorical, staying fully usable as filters and Compare dimensions. `primaryTextField` is repinned to `text` afterwards, because `autoDetectSchema` sets it to the first open-ended field, which may be one just demoted.

Added `--repair-state` to backfill already-ingested datasets without re-inserting 49,046 rows, and it force-recomputes: the non-destructive "skip if schema non-empty" guard silently preserved the very schema being repaired (observed — the first repair reported "kept" and changed nothing). Both prod and test datasets repaired and re-verified. Rewrote `scripts/_verify_trump_corpus.mts` (untracked KEEP) into a readiness check that mirrors what each tab queries — rows vs row_count, dataset_state, schema field count, open-ended set, primaryTextField/primaryDateField, theme_model, tag isolation, empty text — and exits non-zero on failure, so this class of bug is caught before the owner sees it rather than after. Prod: ALL CHECKS PASS on both datasets, `text` the sole open-ended field (avgWords 41.8 / 32.7). tsc clean.

## Trump corpus analysis: theme mining, salience audit, "Silence Gap" report (Aug 7)

WHY: Owner wants talking points for Democratic campaigns, framed as exactly two message types — silence gap ("X matters to you, he never mentions it") and position gap ("here is what he actually thinks") — and narrowed to UNSCRIPTED material only (tarmac/plane/phone interviews/gaggles), not staged speeches. Four scripts: `_trump_corpus_mine.ts` (AI theme mining per half-year slice + a consolidation pass, because mining slices independently rediscovers the same theme under different names and counting it three times makes every share wrong), `_trump_corpus_series.ts` (per-month measurement), `_trump_corpus_salience.ts` (issue attention via explicit auditable keyword lists), `_trump_corpus_audit.ts` (verification of every published number).

Deliberately did NOT build the report on the mined themes: the question is about ABSENCE, which a list of found themes cannot measure, and a per-keyword audit showed some themes are carried by one generic word (a 7.4% theme was 54% "beautiful", another 48% "hearing"). Verification then caught three inflators in my own first draft — (1) 736 endorsement form-letters whose fixed checklist mentions the border in 84% of cases, which had pushed immigration to 13.8% of posts vs 5.1% excluded (ratio to health care 15.2x → 5.5x); (2) a "guns" issue at 10.6% that was 95% the phrase "Second Amendment" from that same checklist, dropped entirely; (3) a ratio table dividing voter-poll % by attention-share %, which are different units on different populations — removed. Also fixed a silent all-zero series: `ThemeScan.perTheme` is a plain number[] aligned to the themes array, so indexing by theme.id (or reading .size) yields undefined and produces data that looks real.

Result: unscripted cut = 384 docs / 25,743 paragraphs. Affordability is equally absent unscripted vs staged (health care 0.7% vs 0.9%; "cost of living" said 3 times in 25,743 unscripted paragraphs; good-paying jobs / uninsured / preschool / affordable housing / minimum wage all zero), so it is not a staffing artefact. Immigration is a script not an instinct (3.0% staged vs 2.1% unscripted); tariffs the reverse (3.0% → 3.9%). Report at ~/Downloads/trump-corpus/REPORT_democratic_talking_points.md carries a corrections section documenting all three inflators so the method survives an opponent checking it.
