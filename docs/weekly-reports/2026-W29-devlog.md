## Fix: service worker no-op fetch handler wedged soft navigation (Jul 13)

WHY: Owner (after the scale-test delete): "Schema comes up the first time after a hard refresh, then when I leave it I can't come back." Root cause candidate with every symptom accounted for: public/sw.js (registered from /m with scope "/", so it controls the whole origin in any browser that ever opened the status page) had a NO-OP fetch listener — pure request-path overhead by its own comments — combined with skipWaiting+clients.claim, which swaps workers over live tabs on every deploy; soft-nav RSC responses then 200 on the server but never reach React, while hard refresh (the one navigation that bypasses a SW) works. Fix: fetch listener removed (v2) — browsers skip no-fetch-handler workers entirely; push + installability (the worker's only jobs) are unaffected; already-installed workers self-update on their next check.
